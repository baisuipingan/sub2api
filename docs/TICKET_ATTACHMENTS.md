# 工单截图

工单截图复用现有 S3/R2 对象存储连接，不依赖异步生图或云端图库开关。

## 启用

系统设置中的对象存储入口会跳转到 **管理员工作台 → 设置 → 对象存储**。
使用已配置的私有桶，清空“公开访问域名”，启用“允许工单截图”后保存。
桶 CORS 沿用本站 GET/HEAD 读取配置；浏览器不直接上传到 S3，不接触存储凭据。

工单截图固定使用 `tickets/v1/`，不受异步生图 `images/` 的七天生命周期影响。
不要给 `tickets/v1/` 配置提前删除规则。关闭上传开关后，已有截图仍可查看和删除；
附件存在时不允许直接切换存储目标，避免旧截图失联。

## 使用及限制

- 新建工单、用户回复、管理员回复，每条最多 3 张静态 PNG/JPEG/WebP。
- 浏览器接受单张不超过 8 MiB 的图片，默认压缩至最长 2560px、单张不超过 2 MiB。
- 截图在点击提交前只保留在浏览器中；最终与文字通过同一次 multipart 请求发送。
- 后端独立检查单张 2 MiB、整个请求 7 MiB、1200 万像素及实际解码结果，拒绝动画。
- 每张保存规范图和 480px 缩略图；消息先加载缩略图，点击才加载清晰图，复用私有图片缓存。
- 同时最多 5 个未关闭工单，`pending`、`replied` 计入，已关闭和已删除的不计入。
- 沿用面板账号 RPM 和原有每用户 10 分钟 5 次建单、30 条消息限制，不新增每日额度。
- 上传读取限时 30 秒，图片处理并发有界，防止慢上传长期占用处理资源。

只有工单本人及具有工单访问权限的管理员可以申请临时链接。签名有效期为 10 分钟，
有效期内可重复读取，并不是一次性链接；RPM 和大小限制也不代表累计存储容量上限。

## 数据与发布

迁移 `254_ticket_attachments.sql` 增加一张附件表，并给原消息表添加可空的操作标识及摘要。
上传对象的已知 key 在写 S3 前持久化，消息和附件在同一数据库事务中提交。
失败立即尝试回收，进程崩溃遗留的上传由后台清理；关闭工单保留图片，删除工单后回收。
重复提交使用现有幂等协调器，并由消息操作唯一键兜底，不重复建单或追加消息。

新开关默认关闭。旧的纯文字 JSON 请求继续可用，升级无需迁移旧工单内容。
该迁移是增加性变更，回退应用时可保留新增表及列；旧版本不会展示附件，也不会运行附件清理。

## 已验证

包含 PostgreSQL 并发建单/重开、同操作并发重试、附件越权与生命周期测试，
服务上传成功/失败及不确定提交测试，HTTP multipart 大小与真实慢连接测试，
前端草稿、缓存、组件和中英文完整性检查，以及桌面和窄屏的本地模拟 API 浏览器检查。
本地验证不使用生产 R2 凭据或向生产提交工单；上线后仍需在实际桶上验证一次上传和读取。
