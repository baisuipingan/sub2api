# 云端参考图提交

云端任务先把参考图存入私有图库，再提交生图任务；上传校验失败时尚未调用模型。
图库支持单张小于 50 MB 的原始图片。普通参考图不再套用项目原有的 2000 万像素限制。

工作台按请求协议检查文件，保留原始参考图的字节、尺寸和 ID，不自动缩到 4096px。
OpenAI Image Edit 明确支持 PNG、JPEG、WebP，每张小于 50 MB、最多 16 张；其普通参考图
文档未规定统一的像素或最长边上限。不要把输出分辨率上限套在输入图上。

遮罩保持 PNG，与目标图具有相同尺寸及有效透明通道，不自动缩图。官方 API Reference
的 mask 字段明确要求小于 4 MB；通用指南另写 50 MB，当前采用端点字段更明确的 4 MB。
带透明区域的请求图属于原有编辑预处理，不改变其与目标图、遮罩的尺寸对应关系。

来源（2026-11-09 核对）：
- https://developers.openai.com/api/reference/ruby/resources/images/methods/edit
- https://developers.openai.com/api/docs/guides/image-generation

原图存储与预览解码需要分开考虑。服务按图片尺寸预估解码内存，在全进程 512 MiB
预算内处理，保留有限转换并发；容量不足返回资源繁忙，而不冒称触犯官方分辨率限制。
云端多图请求当前仍受网关 96 MiB 总输入处理容量限制，并明确区分于官方每图 50 MB。
Gemini、Grok 不套用 OpenAI 文件规则；其原协议参数与限制保持原行为。

提交过程区分准备参考图、上传参考图和提交云端任务。参考图上传最多等 120 秒，
控制接口和每次状态查询最多等 20 秒；停止操作能取消在途上传。状态查询超时后继续查询
原任务，不重新发送付费请求。

后端以安全错误码区分空文件、格式、大小、像素、MIME 及解码失败。日志只记录类别、
允许的 MIME、字节和尺寸，不记录图片内容。有效 JPEG 的 `image/jpg` 和 `image/pjpeg`
别名会规范为 `image/jpeg`，实际格式校验仍保留。

“结果待确认”表示已经进入调用阶段，但没有保存到可确认的完整生成结果。
HTTP 5xx/408、调用中断、空响应或临时文件写入失败可能产生此状态。该状态不证明已经扣费，
也不表示仍在生成；系统不会自动重复调用。错误详情保留实际 HTTP 和脱敏原因。

迁移 `dsapi_005_gallery_official_input_limits.sql` 扩展图库资产的数据库 CHECK；不改历史迁移。
回退到旧镜像后，新保存的超 32 MiB 或超 2000 万像素资产可能无法被旧逻辑读取或编辑，
应使用同样支持这些资产的版本，或按发布策略恢复数据库及对应对象存储快照。

验证覆盖实际大尺寸 JPEG 原样上传和原文件不变、源图与遮罩配对、参考图不重编码、
上传停止与超时、轮询恢复、审计中间件后的二进制完整性，以及 PostgreSQL 未确认状态的
错误保存、脱敏和不重复调用。测试不调用付费模型。
