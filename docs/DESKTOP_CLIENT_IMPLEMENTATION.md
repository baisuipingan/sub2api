# 桌面客户端集成：本轮交付与验证

日期：2026-11-13。Sub2API 与 ZCode 均已完成本轮代码改造，用户已授权复核后发布 Sub2API；正式上线版本、CI、备份及验收结果以不可变 Release 与生产发布记录为准。没有新增数据库迁移、独立积分账本或后台常驻任务。

## 已交付

1. **配置职责整理。** 系统设置的 Agent 页改为“桌面客户端”，保留原入口与配置存储。计费组、公开模型、默认模型、推理档位和单次输出上限集中展示；物理能力与连接兼容配置折叠到高级区域。模型目录不冒充调用权限，调用准入继续复用原用户、Key、分组、余额及限流规则。
2. **官方能力档案。** 不再信任旧随填声明。首批内置已核对的 GPT-6.1 Sol、GPT-6 Astra/Sol/Luna、GPT-5.6 Sol/Terra/Luna 七个档案及官方 `gpt-5.6` 别名；按公开 ID 精确自动匹配，自定义别名一次性关联，保留原路由名、展示名称和默认模型归属。默认高级能力只读，管理员明确启用覆盖后才采用自定义声明，并可恢复档案默认。官方规格与当前执行器能力分开呈现；档案加载失败保留草稿、允许重试并阻止发布。服务器在读取、保存和执行时统一校准能力，不仅修改表单。
3. **托管凭据生命周期。** Key 页按服务端 `purpose=desktop_agent` 提供撤销、重置与确认操作。撤销保留用途行，后续 bootstrap 不会自动复活；本人仅可轮换启用中的 Key，停用后仅完整管理员经现有 step-up 门控显式恢复。轮换/恢复旋转同条 Key 的秘密，保留配额、已用量、过期时间和速率窗口；事务内重验当前调用者身份、管理员角色与 Key 状态。操作影响该用户共享此 Key 的全部设备，尚不是每设备撤销。接口只返回结果，不返回秘密；提交后复用原认证缓存失效机制。
4. **系统浏览器登录。** ZCode 主登录界面改为打开系统浏览器，网站负责登录、验证码、2FA及明确授权。Host 持有 PKCE verifier、state 和临时本机监听；网站只回传短期一次性授权码，Host 换取既有账户会话并沿用现有加密存储。取消、超时、换号及迟到响应均有关闭与隔离处理。

旧 bootstrap protocol 1/2/3 线协议和旧密码/2FA 服务方法保持兼容；新增管理档案元数据不进入 bootstrap 模型。未关联的旧自定义模型停止发布能力，v3 隔离该模型、v1/2 整体拒绝，需管理员一次性关联档案。当前客户端上下文预算保守使用官方最大输入上限；OpenAI 原生网页搜索与显式 none 暂不启用，具体依据见[模型档案合同](./DESKTOP_MODEL_PROFILES.md)。本次未替换模型执行器、现有钱包或网关计费。浏览器登录取得的是现有账户会话，不是新增的受限设备会话；推理仍使用原专用 Key。

## 发布顺序与后续边界

先发布包含授权页、授权码接口和凭据接口的 **Sub2API 后端及前端**，再发布新 ZCode。旧桌面可继续使用旧接口；新桌面的浏览器登录依赖新网站接口，不能反过来先发布。

本次没有数据库结构迁移，但配置 JSON 新增可选 `model_profiles`。**发布前备份 `desktop_agent_config_v1` 的原始值**；保存新配置后，旧二进制的严格解析器不认识该字段，不能只回退镜像。需要回退时，在停用新配置写入的维护窗口内恢复匹配旧版本的该条配置（或使用预先验证的字段兼容转换），再校验旧客户端读取；不能顺带回滚用户余额、用量或 Key 数据。若新桌面已经分发，网站回退到不支持新登录接口的版本还会使其新登录失败，须配合客户端版本安排。已撤销/重置的 Key 状态与秘密不会因代码回退自动恢复，旧秘密也不应恢复。

按增量方案，每设备推理凭据、设备授权管理与每任务费用归集留待后续独立实施。官方档案由代码维护，未引入可在线编辑的全局模型注册中心或自动探测任务。
