# 对话与办公工作台运维交接

本轮运行在独立测试站 `https://llm.editor.vip`，代码分支为
`codex/workbench-office-agent`。生产发布和合入主分支属于后续操作，不能把测试站验收等同于生产变更。

## 入口与配置

个人工作台包括“对话助手”（`/workbench/chat`）、“图片生成”（`/workbench/image`）和“我的文件”（`/workbench/files`）。管理员工作台包括运行概览（`/admin/workbench`）、对话记录（`/admin/workbench/chat`）、用户文件（`/admin/workbench/files`）和工作台配置（`/admin/workbench/settings`）；原图片管理入口保留。

在管理员工作台设置中选择统一的工作台模型分组，向该分组加入公开文本模型和图片模型。沿用每个用户原来的系统工作台 Key，不需要新增聊天 Key。对话只列出分组实际模型；自定义公开别名可明确绑定官方能力档案，不能通过私有上游映射推断语义。

普通对话、办公任务、“我的文件”和联网分别配置。“我的文件”同时控制文件入口与上传；启用办公会同时启用对话与文件，关闭对话会同时关闭办公与联网，关闭文件会同时关闭办公。部署级 `OFFICE_AGENT_ENABLED` 及独立 worker token 是内部运行前提；后台开关负责业务准入。只关闭办公不影响纯文本对话；关闭对话会隐藏对话入口并显示未启用，历史数据仍保留，重新开启后可读。“我的文件”单独开启时仍可使用。完全关闭部署级模块则其 API 不再提供服务。

联网复用“系统设置 → 网关服务 → Web Search 模拟”（`/admin/settings#gateway`）的 Brave/Tavily 供应商配置，工作台设置只控制是否开放联网。未配置凭据时，用户侧不会出现可用的联网开关；配置检测不代表已远程验证凭据或余额，实际供应商仍须联调。不能将模型自身回答当作已搜索。搜索供应商凭据与用户模型 Key 无关。

## 存储和容量

在“工作台配置 → 文件与图片对象存储”（`/admin/workbench/settings#image-storage`）配置办公文件用途；可复用备份 S3/R2 连接，使用独立私有桶。共用的“公开访问域名”必须清空，单独选择办公桶也不例外；桶 CORS 允许本站 GET 读取预览。办公资源为 `workspace/v1/`，与原 `studio/v1/` 图片对象分开。若原图片桶存在自动过期规则，应选择不受该规则影响的办公桶，避免资料或交付件被桶生命周期提前删除。禁止复用 MiloCode 的公开下载桶；已有办公文件时，不能直接修改其存储位置。

原件、不可变版本和预览进入私有对象存储；会话、权限、任务和文件元数据进入原 PostgreSQL。文件列表只读元数据，打开预览或下载才申请临时链接。原有图库通过引用呈现在“我的文件”，不复制整桶；引用保护防止旧图片清理误删仍被对话使用的对象。

当前固定文件边界为单文件和任务工作区各 24 MiB、工作区最多 64 个文件、每用户办公资源 1 GiB/1,000 个版本；原件、版本和预览计容量。不是每位用户一台常驻机器，也不是每次临时读写都请求对象存储。文档修改保存新版本，原会话成果卡仍可读取旧版。

## 运行组件

| 组件 | 职责及边界 |
| --- | --- |
| Go 主站 | 登录、准入、任务、权限、原模型网关和原积分账本；没有 Docker socket |
| chat worker | 轻量文本/检索池；不依赖办公执行器，不加载办公技能 |
| office worker | 持久图、三套办公技能和受控工具；只有短期 run 凭证，没有长期模型 Key |
| executor supervisor | 可信的固定任务容器监督器；仅该组件拥有受控 Docker socket |
| Linux/gVisor 短期任务容器 | 固定办公依赖，无网络/平台凭据，非 root、只读根目录，有 CPU/内存/PID/临时盘/时限约束 |

worker 和 supervisor 只经认证的内部网络或加密通道通信，不开放为公共执行接口。缺少固定镜像或 runsc 时拒绝办公执行，不能降级到主站执行生成代码。具体构建和 token 变量见 [worker 文档](../services/office-agent/README.md) 与 [执行器文档](../services/office-executor/README.md)。测试机的独立 Compose 配置见 [部署说明](../deploy/workbench-office-test/README.md)。

后台任务预算和部署上限分别生效，包括用户并发、模型/工具次数、单次输出、总时长和可选积分预算。官方模型最大能力仍来自官方档案，不被预算改写。一个办公任务可能调用模型多次，每次直接进入原使用记录和积分账本；任务结束不再扣一笔“总费”。

## 状态、恢复和停用

浏览器刷新、重连和查看文件不会重新提交模型任务。澄清等待会保存状态，用户回答后恢复同一个 run；等待时不保留办公容器。未知的在途请求不自动重发，避免重复收费。`needs_confirmation` 表示不能安全断言最终结果，不能简单当作失败后循环重试。

常驻 worker 在尚未取得完整任务清单时，对领取连接中断及 HTTP 429/500/502/503/504 按 5、10、20、30 秒退避，成功领取或空队列响应后重置。主服务更新造成的短暂断连不要求重启空闲 worker；鉴权、契约错误和 `--once` 仍立即失败。这个恢复机制不包围已领取任务的执行、模型调用或完成上报，不能拿它处理结果未确认或重复生成。

遇到异常时按 run ID 查看管理端模型/工具子调用及原上游记录，区分供应商失败、计费待入账、执行异常、存储归档与恢复中断。内部 worker 诊断只记录有限异常分类和 run ID；不记录提示词、文档、密钥或完整堆栈。

日常暂停使用后台的新任务开关，让正在运行的任务排空；紧急中止通过任务取消接口撤销租约。回退应用版本前停止新 worker 和新任务，不删除增量业务表、对象或原账本。已有新文件和会话应保留，不能使用删桶、删表作为功能回退。

功能关闭后，API 网关、图片生成、桌面端、工单、公告等原模块按原配置运行。测试站仅使用独立 PostgreSQL、Redis 和测试私有桶，不接入测试机其他应用的数据和网络。
