# 平台币种与支付改造实施计划

- [x] 统一充值报价和下单校验。USDT 与易支付按平台币种和基础汇率计算。报价过期或配置变化时重新确认，重复提交沿用原订单。
- [x] 更新后台和用户页面。取消单笔币种切换，显示渠道币种、规则适用单位、预计到账和实际到账。BEpusdt 及采用新报价的充值订单隐藏自动退款，后端也会拒绝。
- [x] 验证账务和历史订单。核对两种币种、旧单付款、入账流水、限额、优惠和退款保护。易支付已使用协议模拟验证，真实商户联调安排在启用时。
- [x] 发布并核对线上。镜像在本机构建，部署前备份 PostgreSQL。用生产美元订单核对报价、下单、收银台、查询、回跳和取消，复核原有订单及余额流水。

生产版本为 `0.2.24-ds.5`，平台币种 USD，汇率 1 USD = 6.75 CNY，开放 USDT（BEP20）。微信、支付宝和易支付处于停用状态。后台沿用人民币等值维护限额和优惠门槛，现有最低 ¥1 在美元充值页显示为 $0.15。

隔离环境使用真实 PostgreSQL 验证了重复请求只创建一笔渠道订单，重复回调只写一笔积分流水。美元 $3 和人民币 ¥20.25 的订单均发放 300,000,000 credits，人民币 ¥10 的易支付模拟订单发放 148,148,148 credits。套餐使用已发布的原币价格，并验证了支付成功后的权益发放。

首个发布的 `ds.4` 在真实接口省略 `available` 字段时错误禁用了充值按钮。最终镜像 `ds.5` 修复了该判定并通过两种币种的浏览器验收。生产订单 #11 和 #12 已取消，#12 的充值流水为零。历史实付订单 #8 仍为已完成，账本只有一笔 300,000,000 credits。本次生产验收使用未付款订单，真实支付回调及入账通过隔离环境模拟验证。

当前的按用户每日充值上限会预留待支付额度。渠道实例的跨用户日限额继续使用下单前检查。自动退款的精确积分冲减作为后续独立改动处理。
