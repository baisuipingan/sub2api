# 二开版本探测、发布与回退流程

## Why

当前 Sub2API 的左上角版本徽标会把“官方是否有新版本”和“是否允许在当前进程内替换可执行文件”绑定在一起。官方 Release 构建会从 GitHub 下载二进制，原子替换当前可执行文件并重启。这个流程适合官方独立二进制部署，却不适合当前二开项目：

- 二开镜像包含本地计费和配额改造，直接安装官方二进制会覆盖二开代码。
- Docker 部署中替换容器内二进制只是临时修改；下一次 `docker compose up` 或镜像更新会丢失。
- 数据库迁移是向前执行的，页面上的“回退版本”不能单独保证数据兼容。
- 二开版本号与官方版本号属于不同发布序列，直接用 SemVer 比较会把两个序列混在一起。
- 更新、回退应当经过测试、构建、备份、灰度、健康检查和数据库兼容策略，不能由管理页面瞬时执行。

目标是把版本徽标改成“官方上游变化提醒器”，把发布和回退改成“带审计的镜像流水线”。

## What Changes

- 引入三个互相独立的版本概念：
  - `release_version`：当前二开镜像版本，例如 `0.2.18-ds.1`。
  - `upstream_version`：本次构建已经审查并合入的官方版本，例如 `0.2.18`。
  - `latest_official_version`：GitHub 官方仓库当前最新正式版本。
- 左上角继续探测 `Wei-Shaw/sub2api` 的 GitHub Release，但高亮条件改为：
  `latest_official_version > upstream_version`。
- 管理端显示当前二开版本、官方基线、官方最新版和官方 Release Notes。
- 更新按钮保留为禁用状态并解释“请使用二开发布流程”；官方页面上的自更新和页面回退接口在服务端也返回禁用错误，不能只依赖前端隐藏。
- 新增二开版本元数据、标签规范和 GitHub Actions 发布流水线。发布产物为不可变的 GHCR 镜像标签与 digest，并附构建清单。
- 发布命令创建版本标签并推送，由 CI 完成全量检查、构建、镜像发布和 Release 创建。
- 服务器使用发布脚本部署指定版本：备份数据库、拉取不可变镜像、重建单个服务、健康检查；失败时自动恢复上一镜像。
- 提供显式回退命令。数据库变更采用 expand/contract，保证至少一个发布周期内应用可回退。
- 左上角在新镜像部署后自动消警，因为镜像内嵌了新的 `upstream_version`；不需要额外点击“已读”。

## Capabilities

### New Capabilities

- `upstream-release-notification`：官方 Release 探测、基线比较、只读提示和消警行为。
- `fork-release-pipeline`：二开版本命名、发布前校验、CI 构建、GHCR 镜像、构建清单与 Release 产物。
- `fork-release-deployment`：指定镜像部署、数据库备份、健康检查、自动回滚和显式版本回退。

### Modified Capabilities

- `admin-version-management`：保留版本状态和官方 Release Notes 的只读能力，禁用在线二进制更新和页面回退。
- `docker-deployment`：生产容器从固定 `latest` 改为显式二开镜像引用。

## Non-Goals

- 不实现自动合并官方代码。官方 Release 只负责提醒，是否合并由维护者审查。
- 不提供管理页面一键部署；所有生产变更通过明确版本号的命令执行。
- 不允许容器在运行时下载并替换 `/app/sub2api`。
- 不在第一版实现多节点滚动发布。单机部署通过最短停机重建、健康检查和自动回滚提高可用性。
- 不把官方版本号直接当二开版本号，也不对两个发布序列做大小比较。

## Impact

- 后端：扩展 `UpdateInfo`、构建信息和系统设置接口；禁用写操作路由；增加元数据测试。
- 前端：版本徽标、下拉内容和 API 类型；移除自动更新按钮的可执行路径，改为禁用说明和官方 Release 链接。
- 构建：新增 `UPSTREAM_VERSION` 编译期元数据、版本规范、二开发布工作流和发布前脚本。
- 部署：Docker Compose 使用 `${SUB2API_IMAGE}` 固定镜像，新增服务器发布/回退脚本和状态目录。
- 数据：版本基线使用编译期元数据，不新增数据库表；部署脚本额外保存数据库备份和镜像 digest 状态。
- 运维：上线前需要配置 GHCR 可见性或服务器拉取凭据，并完成一次 staging 发布与回退演练。

## Success Criteria

- 官方发布 `v0.2.18` 后，当前基线为 `v0.2.17` 的二开镜像显示高亮和 Release Notes。
- 管理页面没有可执行的更新或回退提交入口；直接调用旧接口返回明确错误。
- 发布并在生产部署 `0.2.18-ds.1` 后，徽标高亮消失，显示基线 `v0.2.18`。
- 同一版本标签不能重复发布，生产环境不引用可变标签。
- 部署失败时，上一镜像在健康检查窗口内恢复；数据库备份路径和两次镜像 digest 均被记录。
- 回退命令可在一次操作内恢复上一二开版本，且 expand/contract 迁移策略允许应用层回退。
