# 人民币计费与自由切换（积分账本）

## Why

Sub2API 当前的余额、用量扣费、API Key 配额、订阅额度、平台限额和大量前端展示都隐含 USD 语义。支付渠道虽然已经支持 CNY，但内部账本并没有真正的人民币单位，也没有能在 USD/CNY 之间自由切换的统一账务模型。

直接全局替换 `$`、重命名 `*_usd` 字段，或直接按汇率改写历史余额，会造成余额漂移、退款无法复算和历史账单不一致。

## What Changes

- 新增固定整数的内部账本 `credits`，作为余额、订阅额度和用量统计的唯一内部单位。
- 新增展示币种 `USD/CNY` 和展示汇率；切换币种只改变 UI，不改变余额或已发生扣费。
- 新增充值售价与展示汇率分离的配置，支持人民币渠道、美元渠道、折扣和手续费。
- 保留模型价格目录的上游 USD 计价，在最终扣费边界一次性换算为 credits。
- 为订单、用量日志和账务流水增加汇率与价格快照，保证历史可复算。
- 提供 `legacy → shadow → credits` 的灰度切换和对账机制。
- 统一前端货币格式化，移除散落的 `$`、`¥` 和手工 `toFixed` 金额展示。

## Non-Goals

- 不为同一用户同时维护 USD 钱包和 CNY 钱包。
- 不重写上游模型价格目录，也不在请求热路径调用第三方汇率接口。
- 不在第一版删除旧 USD 字段或立即破坏旧 API 兼容性。
- 不改变支付网关的原生币种能力。

## Impact

- 后端：Ent schema、SQL 迁移、用量扣费、缓存预扣、充值履约、退款、兑换码、返利、订阅和平台额度。
- 前端：余额、充值、订单、订阅、用量、Key 配额、管理端价格配置和邮件模板。
- 运维：需要一次数据回填、shadow 对账、灰度切流和回滚预案。

## Success Criteria

- USD/CNY 切换后，余额对应的扣费能力保持不变，历史订单和扣费流水不被重算。
- 同一请求重复回调或异步重试最多扣费一次。
- 用户余额、API Key 配额、订阅用量、平台限额和 usage_logs 能在同一账期内精确对账。
- 人民币充值的实付金额、到账 credits 和订单快照一致。
- 文本、图片、视频、搜索、音频和批量任务全部经过同一个积分转换入口。
